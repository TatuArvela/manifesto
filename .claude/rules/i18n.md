# Internationalization

`src/i18n/` contains two catalogues, `messages/en.ts` and `messages/fi.ts`. English is the source of
truth for keys (`MessageKey = keyof typeof en`). Thus, put a new string in `en.ts` first. The
typecheck then requires the string in `fi.ts`. Tests make sure that:

- The two catalogues have the same keys.
- Each Finnish plural has a `.other` form.
- Neither catalogue contains the product name as a literal.

`t()` reads the `locale` signal internally. Thus, **call it inside component render bodies**, never
at module scope. If you call it at module scope, the string stays in the locale from load time.
`plural()` selects the form through `Intl.PluralRules`, and sets `{count}` to `n` by default. Units
and separators come from `Intl`, not from the messages (`formatFileSize` shows "MB" or "Mt"). Thus,
a translator does not have to know the local convention.

Only English is in the entry chunk. Each other catalogue is a separate chunk:

- `catalogueLoaders` (`messages/index.ts`) lists the chunks.
- `loadCatalogue`, in the same file, gets them.
- `t()` and the formatters read the language on the screen. That language changes to `locale` only
  when its catalogue is available. Thus, a change of language never shows English for a moment.
- `main.tsx` loads the saved language before the first render.

To add a language, add a line to `catalogueLoaders`. Do not import its catalogue statically, because
that puts the catalogue in the download of each user again.

The setup of the browser tests loads Finnish one time. Thus, a test that sets
`locale.value = "fi"` reads Finnish on the next line. The setup loads it through
`messages/index.ts`, never through `i18n/index.ts`. The reason is that `i18n/index.ts` imports
`config.js`. A module that the setup loads, loads before the `vi.mock` of that module in a test
file, and then the `vi.mock` has no effect.
